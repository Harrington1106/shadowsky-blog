新手最常撞上的一个坎：宝塔装完提示「安装成功，请访问 http://IP:8888」，复制到浏览器里转半天，最后无法访问。

这不是装错了。云服务器出厂时出于安全考虑，默认只开 22 端口（SSH），80、443、8888、5700 这些全是关着的。你得手动去云厂商控制台把它们放行。

## 一、端口是什么

可以把服务器想成一栋楼：

```text
服务器 IP（比如 47.118.28.27）= 大楼地址
  ├── 22 号房   → SSH 远程连接（默认开着）
  ├── 80 号房   → 网站 HTTP（默认关着）
  ├── 443 号房  → 网站 HTTPS（默认关着）
  ├── 8888 号房 → 宝塔面板（默认关着）
  ├── 5700 号房 → 青龙面板（默认关着）
  └── 3306 号房 → MySQL（默认关着，建议一直关着）
```

防火墙是这栋楼的门卫。你得先告诉门卫「8888 号房可以进人」，访客才进得去。

## 二、怎么放行（以阿里云为例）

### 轻量应用服务器

1. 进入[轻量应用服务器控制台](https://swas.console.aliyun.com)
2. 点你的服务器 → 左侧「安全」→「防火墙」
3. 点「添加规则」，按下表填：

| 字段 | 填什么 |
|------|--------|
| 协议 | TCP |
| 端口 | 8888（宝塔）/ 5700（青龙）/ 80（网站） |
| 来源 | 0.0.0.0/0，允许所有人访问 |

4. 保存，立即生效，不用重启。

### ECS 云服务器

1. 进入 [ECS 控制台](https://ecs.console.aliyun.com)
2. 点实例 →「安全组」→「配置规则」→「入方向」
3. 点「手动添加」，字段同上
4. 保存

其他云厂商只是叫法不同：腾讯云叫「安全组」，AWS 叫 Security Group，Azure 叫「网络安全组」，操作逻辑一样。

## 三、常用端口速查

| 服务 | 端口 | 说明 |
|------|------|------|
| SSH | 22 | 远程连接，别关 |
| HTTP | 80 | 网站默认端口 |
| HTTPS | 443 | SSL 加密网站 |
| 宝塔面板 | 8888 | 建议装完就改成冷门端口 |
| 青龙面板 | 5700 | |
| qBittorrent | 8080 | BT 下载器 WebUI |
| Jellyfin | 8096 | 媒体服务器 |
| Alist | 5244 | 网盘挂载 |
| Portainer | 9443 | Docker 可视化管理 |
| Uptime Kuma | 3001 | 网站监控 |

数据库端口单独列出来，因为这几个不要对外开放：

| 服务 | 端口 | 风险 |
|------|------|------|
| MySQL | 3306 | 只允许 localhost 访问 |
| Redis | 6379 | 务必设密码 |
| PostgreSQL | 5432 | 同上 |
| MongoDB | 27017 | 默认无密码，最容易被扫 |

## 四、放行了还打不开

按这四步往下查，基本能定位。

### 确认端口在监听

```bash
netstat -ntlp | grep 8888
```

没有输出，说明服务压根没启动，或者没绑到这个端口上。

### 检查系统级防火墙

云控制台放行了还不够，服务器系统内部也有一层：

```bash
# CentOS
systemctl status firewalld
systemctl stop firewalld     # 仅用于临时排查

# Ubuntu / Debian
ufw status
ufw disable                  # 仅用于临时排查
```

关掉只是为了确认问题出在这一层，查完记得开回来。

### 确认服务绑定地址

有些服务默认只绑 `127.0.0.1`，也就是只有本机能访问，需要在配置文件里改成 `0.0.0.0`。

### 用 telnet 测连通性

```bash
# 在自己的电脑上跑，不是在服务器上
telnet 47.118.28.27 8888
```

显示 `Connected` 说明端口通了；一直停在 `Trying...` 就是不通。

## 安全建议

- 宝塔的 8888 装完就改掉，换个五位数的冷门端口
- MySQL 的 3306 不要对外开放，被扫到就是持续的暴力破解
- Redis 的 6379 不设密码就开放，等于把服务器钥匙挂在门口

## 小结

排查顺序固定下来就不会乱：先看云控制台防火墙，再看系统内部防火墙，然后确认服务在监听，最后用 telnet 测连通性。

多数情况在第一步就解决了。
