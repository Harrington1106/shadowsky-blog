青龙面板是一个跑在服务器上的定时任务管理平台，支持 Python3、JavaScript、TypeScript 和 Shell 四种脚本。

它出圈是因为「薅羊毛」——自动签到、自动领京豆、自动抢券。但那只是它的一类用法，本质上它管的是「到点执行某个脚本，并且把结果告诉你」。

## 一、薅羊毛

最广为人知的用途，是自动完成各类 App 的每日任务：

| 平台 | 能自动做的事 |
|------|-------------|
| 京东 | 签到、浇水、喂鸡、领京豆、抢券 |
| 饿了么 / 美团 | 领红包、吃货豆 |
| Bilibili | 登录、看视频、投币、分享 |
| 阿里云盘 | 每日签到领空间 |
| 百度网盘 | 自动签到 |

原理并不神秘：你把自己账号的 Cookie 填进脚本，脚本到点了就带着这个 Cookie 去模拟你的操作。所以下面「风险」那一节请务必看完再动手。

## 二、其他签到场景

除了电商平台，常见的还有：

- 机场签到，自动领流量
- 论坛、贴吧签到，保持账号活跃
- GitHub 签到，维持贡献图的绿格子

想加新任务，去 GitHub 搜「青龙面板 脚本」，开源脚本库很多。复制进青龙，设好定时就能跑。

## 三、消息推送

任务跑完之后可以自动发消息通知，支持的渠道不少：

| 渠道 | 适合场景 |
|------|----------|
| Server 酱 | 微信接收，配置最简单 |
| 企业微信 | 团队使用 |
| Telegram Bot | 海外网络环境 |
| 钉钉机器人 | 办公场景 |
| PushPlus | 图省事 |

配好之后收到的消息大致长这样：

```text
[京东] 签到成功，获得 5 京豆
[B站] 投币完成，今日经验 +50
[饿了么] Cookie 过期，请重新获取
```

最后那类消息才是推送真正的价值所在。Cookie 失效是常态，没有推送的话，你可能一个月后才发现脚本早就白跑了。

## 四、比 Crontab 好在哪

Linux 自带的 Crontab 也能跑定时脚本，差别在依赖管理。

脚本通常要用到 `axios`、`requests`、`pandas` 这些库。用 Crontab 的话得手动一个个 `pip install` 或 `npm install`，换台服务器再来一遍。

青龙把这一步做成了图形界面：打开依赖管理页，搜库名，点安装。Node.js 的、Python 的、Linux 系统包都在同一个地方装。

## 五、风险

这一节比前面几节都重要。

### 账号安全

Cookie 约等于账号密码。交给第三方脚本，等于把钥匙给了别人。降低风险的几个做法：

- 只用 GitHub Stars 超过 500 的知名脚本库
- 跑之前翻一遍源码，确认没有往陌生地址发数据
- 高风险脚本用小号跑
- 定期更换 Cookie

### 风控封号

频繁的自动化操作可能被平台判定为机器人，后果从轻到重是：领不到券（提示「活动太火爆」）、账号被降权、直接封号。

所以别 24 小时不停地跑，把执行间隔设得合理一些，一天一次通常就够。

## 快速上手

```bash
docker run -dit \
  --name qinglong \
  --restart always \
  -p 5700:5700 \
  -v /opt/qinglong/data:/ql/data \
  whyour/qinglong:latest
```

装好后访问 `http://你的IP:5700`，按引导完成初始化，再去找具体的脚本配置。

## 小结

抛开薅羊毛，青龙能做的事还有不少：定时抓数据、定时备份文件、定时检查网站状态、定时清理服务器垃圾。

只要能用脚本描述的重复劳动，都可以扔给它。
