社交媒体已经很发达了，为什么还要有个人网站。

我的答案是数据归属。平台上的内容受算法分发、受审核规则约束，账号本身也可能消失。自己的网站不解决流量问题，但它解决归属问题。

想建站的人常被术语劝退：域名、服务器、DNS、CDN、SSL、ICP。其实可以套盖房子的类比来理解——域名是门牌号，服务器是地皮，CDN 是通往各地的路，备案是登记手续。下面按这个顺序过一遍。

## 一、域名

域名是网站的地址，比如 `google.com`。没有它，别人只能记一串 IP。

### 后缀怎么选

| 后缀 | 特点 |
|------|------|
| `.com` | 最经典也最贵，好名字基本注册不到了 |
| `.io` / `.me` / `.dev` | 开发者常用，个性明确 |
| `.xyz` / `.top` | 便宜，适合学生或测试 |
| `.cn` | 中国国家域名，必须实名认证，解析到国内服务器通常还要备案 |

### 去哪买

国外可以选 NameSilo、Porkbun 或 Cloudflare，价格透明，Cloudflare 还送隐私保护。国内阿里云、腾讯云更方便，但监管相对严格。

买的时候一定要确认有没有 Whois 隐私保护。没有的话，你的姓名、邮箱、电话会被公开在网上，接下来就是持续不断的骚扰电话。

## 二、服务器与托管

网站的代码要放在某台机器上，这一步有两种路线。

### 方案 A：自己买服务器

阿里云 ECS、腾讯云 CVM、AWS EC2、DigitalOcean 都属于这一类。

你拿到的是一整个 Linux 系统，想装什么装什么，博客、网盘、游戏服都行。代价是要懂点 Linux 命令，安全要自己维护，每月还有几十到几百的费用。

适合爱折腾的人，以及需要跑后端程序（PHP、Java、Python）的网站。

### 方案 B：静态托管平台

Vercel、Netlify、GitHub Pages、Cloudflare Pages 属于这一类。

完全免费，代码传上去自动部署，自带全球 CDN 和 SSL 证书。限制是只能托管静态内容（HTML/CSS/JS），跑不了 PHP 和 MySQL——不过这部分需求通常能用第三方 API 补上。

绝大多数个人博客、文档站和作品集，选这个就够了。

## 三、技术栈

### 方案 A：动态博客系统

WordPress、Typecho、Halo 都属于这一类。

每次有人访问，服务器从数据库查数据再拼成网页。好处是功能全、插件多、有后台界面、所见即所得。前提是你得先有一台服务器，也就是上一节的方案 A。

### 方案 B：静态站点生成器

Hexo、Hugo、Astro、Next.js 属于这一类，也是现在的主流。

流程是：你在本地写 Markdown，工具把它编译成纯 HTML，再传到 Vercel 这类平台。

优势有三个：快（不用查数据库）、安全（没有数据库就没有注入）、托管免费。代价是通常没有后台，得习惯写 Markdown。

我现在的网站就是这套架构。

## 四、备案与认证

这部分取决于服务器在哪。

### ICP 备案

只针对**国内服务器**，而且是强制的，不备案网站会被阻断。

流程是拍照、核验、等管局审核，一般 7 到 20 天。

### 非官方认证

博客托管在海外（Vercel、GitHub）的话不需要 ICP 备案。但可以申请几个社区性质的认证：

- **萌 ICP 备**：二次元圈的娱乐性备案，纯粹为了好玩
- **十年之约**：承诺博客运行十年的博主公约
- **开往**：加入友链列车，让陌生访客随机跳转到你的博客
- **公网安备**：公安系统的备案，国内建站通常也要做

### CC 协议

这不算备案，但对内容创作者有实际作用。在页脚声明 CC 协议（比如 `CC BY-NC-SA 4.0`），等于明确告诉访客：

- BY（署名）：转载要标注你的名字
- NC（非商业）：不能拿你的文章赚钱
- SA（相同方式共享）：改过的作品也要按同样协议发布

## 五、写作工具

### Markdown

互联网写作的通用格式，用简单符号代替排版：`#` 是标题，`**` 是加粗，`>` 是引用。

学会它之后，在知乎、掘金、GitHub 上写东西都是同一套语法。

### 编辑器

- **Obsidian**：支持双向链接，适合同时当知识库用
- **Typora**：所见即所得，排版体验最舒服
- **VS Code**：配合插件写博客很强，程序员的顺手选择

### 图床

不要把图片直接放进代码仓库，仓库体积会迅速膨胀，部署也会变慢。

推荐用 PicGo 配合对象存储（阿里云 OSS、腾讯云 COS、七牛云）。截图之后自动上传、自动生成 Markdown 链接，粘贴进文章就行。

## 六、周边服务

- **DNS 解析**：把域名指向服务器。推荐 Cloudflare，解析快，还免费带 DDoS 防护
- **CDN**：在各地建分发节点让用户就近访问。Vercel 和 Cloudflare 自带
- **SSL 证书**：地址栏那个锁，现在基本都是免费自动签发
- **访问统计**：Google Analytics 功能全，不蒜子简单开源，Umami 对隐私友好
- **评论系统**：静态博客没数据库，可以用 Giscus（基于 GitHub Discussions，免费无广告）、Waline / Artalk（要自己部署后端，功能更强）或 Twikoo（基于腾讯云开发，免费额度够用）

## 七、备份

**版本控制**：把博客源码托管在 GitHub。每次修改都有记录，随时能回滚。

**3-2-1 原则**：3 份副本（本地、GitHub、云盘），2 种介质，1 个异地备份。

Markdown 在这里有个额外的好处：文章就是纯文本，体积小，备份成本几乎为零。哪天网站没了，文字还在。

## 关于心态

建个人网站不是为了流量，也不太可能变现。

有几点是我自己的体会：

不要追求完美，从第一篇写得不怎么样的文章开始就行。也不要用短视频的节奏要求它——现在的互联网太快了，博客是慢的，可能一年只有几个人看，但几年后回头翻，它确实记录了你的变化。

通过「开往」「十年之约」这类组织，还会发现有一批人在同样默默地耕自己那块地。

## 给新手的组合

如果你不是程序员，想尽快有一个能用的博客，直接照抄这套：

1. 域名：NameSilo 买 `.com`
2. 托管：Vercel，免费
3. 技术：Hexo 或 Astro
4. 图床：PicGo 加阿里云 OSS
5. 评论：Giscus
6. 认证：萌 ICP 备加 CC 协议

零服务器成本，维护简单，速度快，数据都在自己手里。
