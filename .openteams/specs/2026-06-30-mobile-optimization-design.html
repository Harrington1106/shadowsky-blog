移动端显示优化

目标是在不重做页面结构的前提下，提升手机宽度下的稳定性、可读性和交互舒适度。改动会优先落在共享样式和页面级响应式补丁，避免触碰数据逻辑与部署流程。

当前上下文

  • 全站静态 HTML 页面已经使用统一移动菜单结构：homepage-mobile-menu-link。
  • 共享移动端样式集中在 css/style.css，页面样式分散在 css/liquid-*.css。
  • 最近提交集中修复 post.html 的移动端横向溢出，说明文章页仍是高风险点。
  • 项目约束要求修改模板或样式时兼顾 14 个 HTML 页面，并保持导航图标与菜单一致。

推荐方案

采用“共享兜底 + 重点页面微调”。先在共享层处理视口宽度、移动菜单、安全区和通用溢出，再针对文章、博客、随手拍、收藏、RSS、ACG 页面做小屏规则补强。

共享层

让导航、移动菜单、公共容器、浮动按钮在 320-430px 宽度下保持在视口内，不压住正文。

页面层

只补每页已有组件的响应式规则，例如工具栏换行、横向分类滚动、正文表格滚动和卡片间距。

具体设计

  • 全站：增加移动端宽度防线，保证 html、body、主要 shell 和菜单不会产生页面级横向滚动。
  • 移动菜单：小屏下菜单宽度使用视口约束，贴近右侧但保留边距；菜单项保持 44px 以上触控高度。
  • 文章页：优化 .post-shell、.post-hero-content、.post-body .prose、表格和代码块，让长标题、长链接、代码和表格不会撑破视口。
  • 博客页：让搜索、视图切换、标签区域在手机上自然换行或横向滚动，文章卡片保持单列阅读节奏。
  • 随手拍和收藏：收紧 header/toolbar 间距，搜索框独占可用宽度，分类 chip 横向滚动但不影响页面宽度。
  • RSS 和 ACG：检查侧栏、列表、播放器和筛选栏在移动端的宽度约束，避免浮层或 iframe 越界。

非目标

  • 不重做视觉体系，不改变现有液态玻璃风格。
  • 不改后端、API、Bangumi 同步或部署脚本。
  • 不批量重写 14 个 HTML 模板，除非验证发现某页结构本身导致移动端问题。

验证计划

  • 用代码搜索确认所有 HTML 保持统一移动菜单和 viewport。
  • 重点检查 320px、375px、430px、768px 宽度下是否出现页面级横向滚动。
  • 浏览关键页面：index、blog、post、moments、bookmarks、rss、acg。
  • 若可启动本地服务，用移动端视口截图验证导航、工具栏、正文、浮层、播放器和底部浮动按钮。

实施顺序

  • 先改 css/style.css 的共享移动端规则。
  • 再改 css/liquid-post.css 处理文章页高风险内容。
  • 最后按页面影响面补 liquid-blog.css、liquid-moments.css、liquid-bookmarks.css、liquid-rss.css、liquid-acg.css。
  • 每一步都用搜索和视口检查确认没有破坏桌面端既有布局。
