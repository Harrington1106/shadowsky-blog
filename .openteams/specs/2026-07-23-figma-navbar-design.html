Design Spec · Approved Direction D

Figma 风导航栏动画 + 液态玻璃增强

ShadowQuake Blog · 2026-07-23 · 全站 14 页统一适配

1. 目标

把现有液态玻璃药丸导航升级为 Figma 式精密动效：

  • 独立滑动指示器（active pill）在导航项之间 spring 滑动，并随宽度变化
  • 当前页展开「图标 + 文字」；其余项仅图标
  • 悬停幽灵层跟随非当前项，不与 active 抢戏
  • 同步增强 navbar 液态玻璃（折射边、高光、模糊层次）
  • 所有带统一 navbar 的公开页面行为一致；尊重 prefers-reduced-motion

2. 已确认决策

项决策
动画风格方案 D：滑动指示器 + 当前页展开标签 + spring 悬停
桌面端图标为主；active 展开中文标签
移动端保留现有汉堡 + 抽屉菜单；不启用滑动指示器
玻璃效果在现有 Aqua Vitrum 体系上增强 navbar 壳层，不重做全站玻璃系统
主题暗色 / 亮色双套 token，与现有 teal 色系一致
跨页动画页面跳转后定位到 active（无跨文档 FLIP）；页内 hover/click 可动画

3. 架构

3.1 职责拆分

CSS · unified.css

  • 导航项布局改为可伸缩宽度（去掉固定 38×38 死宽）
  • active 显示 .nav-text
  • 指示器 / 悬停幽灵样式与 spring transition
  • navbar 玻璃层（背景、边框折射、内高光）增强
  • reduced-motion 降级

JS · navbar.js

  • 注入 .nav-indicator 与 .nav-hover 元素
  • 测量 active 几何，用 transform + width 定位
  • hover / resize / 字体加载后重算
  • 保留 scroll、mobile menu、theme、active 检测

3.2 DOM 结构（逻辑目标）

<div class="nav-links">
  <span class="nav-hover" aria-hidden="true"></span>
  <span class="nav-indicator" aria-hidden="true"></span>
  <a class="nav-link active"><i>…</i><span class="nav-text">首页</span></a>
  <a class="nav-link">…</a>
  …
</div>

指示器由 JS 注入，无需改 14 份 HTML 手写重复节点。HTML 侧仅需确保 .nav-links + .nav-text 已存在（现状已满足）。

3.3 定位算法

  1. 取 .nav-links 与目标 .nav-link 的 getBoundingClientRect()
  2. x = target.left - parent.left，w = target.width
  3. 设置指示器 width 与 transform: translateX(x)（GPU 友好）
  4. 切换 active 时：先更新 class（触发文字展开）→ rAF 双帧测量 → 可选 80ms / 320ms 二次对齐，避免 max-width 动画中途量错
  5. 悬停非 active：移动 .nav-hover 并显示；离开容器则隐藏

4. 动效参数

属性值说明
指示器移动420ms cubic-bezier(0.34, 1.35, 0.64, 1)轻微 overshoot，Figma spring 感
指示器宽度同 420ms spring随展开标签变宽
悬停幽灵280ms cubic-bezier(0.22, 1, 0.36, 1)更干脆，不抢 active
标签展开380ms spring · max-width + opacity仅 .active .nav-text
图标悬停translateY(-1px) scale(1.04)active 项不做额外位移
reduced-motiontransition: none；直接跳位a11y 必须

优先复用 tokens：--ease-spring 可微调为指示器专用 --ease-nav-spring，避免全站其他 spring 过冲。

5. 液态玻璃增强（navbar 壳）

范围限定 #navbar，不推翻全站 glass token。

暗色

  • 背景：多层半透明 + 略提高 blur（20→24px 常态，scrolled 28px）
  • 边框：保留 teal 细线 + 加强 ::before 上下折射渐变
  • 内高光：顶部 1px 白边 inset 更清晰
  • 指示器：独立玻璃片（半透明 teal 渐变 + 细描边 + 外发光）

亮色

  • 背景不透明度 ≥ 0.72，避免「看不见的玻璃」
  • 边框 rgba(20,184,166,.22) 级可见
  • 指示器：浅 teal 渐变 + 柔和阴影，对比度达标
性能约束： 仅 navbar 使用较高 backdrop-filter；指示器本身用实色半透明 + box-shadow，不再套第二层 blur，避免移动端掉帧。

6. 页面适配范围

页面处理
index, blog, moments, bookmarks, rss, acg, about, post, 404, edits…共用 navbar.js + unified.css，自动获得动效
anime / manga / gnz48 / moments-old（若含同一 navbar）同样依赖；验证脚本引用版本号 bump
admin/OUT 管理后台独立 UI，不在本次范围
ai-daily/OUT 除非使用同一 navbar 结构

HTML 改动预期：几乎为零（仅 bump ?v= 缓存参数）。若个别页缺少 .nav-text 或结构偏差，做最小补丁。

7. 冲突清理

  • 移除 / 覆盖 unified.css 顶部 a.nav-link::after 下划线动画（与滑动指示器语义冲突）
  • active 态背景从「链接自身 background」改为「指示器层」；链接背景透明，避免双重底
  • 保留 icon glow（drop-shadow），与指示器叠加

8. 无障碍与降级

  • 指示器 / 悬停层 aria-hidden="true"，不进读屏
  • active 仍用 aria-current="page"（现有 + JS 可补）
  • 键盘 focus-visible 描边保留在链接上
  • 触控设备无 hover 幽灵；仅显示 active 指示器
  • prefers-reduced-motion: reduce：无 spring、无宽度过渡

9. 实现步骤（计划草案）

  1. 扩展 navbar.js：注入层、定位、事件、resize、reduced-motion 检测
  2. 更新 unified.css 导航与玻璃样式；加 --ease-nav-spring token（可选在 design-tokens）
  3. 去掉冲突的 underline pseudo
  4. 全站 HTML 的 navbar.js / unified.css 版本号 bump
  5. 目检：暗/亮、桌面 hover/click、窄屏汉堡、首页透明/流体背景上的可读性

10. 验收标准

  • 桌面端切换当前页后，指示器落在正确项且宽度贴合「图标+文字」
  • 悬停非当前项时幽灵层平滑跟随；当前项无双重底
  • 暗色 / 亮色玻璃边与文字对比清晰
  • 移动端菜单行为与现网一致
  • reduced-motion 下无滑动动画
  • 不引入 layout shift（navbar 高度稳定）

11. 明确不做

  • 跨页面 FLIP / View Transitions API（可作为后续增强）
  • 重写移动端为底部 tab bar
  • 全站所有卡片的玻璃体系大改
  • 引入 React/动画库（纯 CSS + 原生 JS）
